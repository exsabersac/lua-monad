# 版本与路线

当前主线为 **0.2.17-eng**（Unity + Lua 5.3，工程可用闭环已达标；**eng 工具波次收口**）。本页把 0.2.3–0.2.11 的增量和 Unity 接入阅读顺序收口在一起。

## 0.2.3–0.2.11 版本亮点

| 版本 | 亮点 | 对工程的意义 |
|------|------|--------------|
| **0.2.3-eng** | `abort`/`stop` 分流、`iquit → finally`、`fx.seq`、flow suspend/resume | 生命周期和退出语义可明确对照 tabMachine |
| **0.2.4-eng** | Cont 热路径、`chain`/`map`、bench 与 trace 工具 | 减少组合开销，具备可复测的性能入口 |
| **0.2.5-eng** | `fx.run` 无 Yield 同步快路径 | 纯同步 flow 不必建立完整 session/pump |
| **0.2.6-eng** | 有界 `chan` / mailbox、send/recv/close | 多 flow 可用背压和取消协作，避免 busy wait |
| **0.2.7-eng** | `fx.supervise` 监督式重启 | 对 Failed 做有界重启；取消和 abort 不误重启 |
| **0.2.8-eng** | Unity Bootstrap、`fx.wait_real`（opt-in） | scaled 游戏时间接入有模板；墙钟等待明确隔离 |
| **0.2.9-eng** | `fx.lane` / `lanes` / `lane_join` | 以命名子流轻量对照 tabMachine `c:start` |
| **0.2.10-eng** | `fx.proxy` / `flow:proxy` 与 join/stop/abort | 以不拥有 Cont 的句柄轻量对照 `tabProxy` |
| **0.2.17-eng** | 复杂示例波次（护卫 / 工人池） | `examples/escort_mission/`、`examples/worker_pool/`；lanes/proxy/chan/supervise/背压 |
| **0.2.16-eng** | 工具套件收口 + baseline 刷新 | `docs/工具套件收口.md`；`bench_baseline.json` 本机重种（N=20000） |
| **0.2.15-eng** | 共享 scenarios + 工具速查 | `tools/scenarios/`；`docs/工具速查.md`；profile/trace/bench 复用 |
| **0.2.14-eng** | profile_flow 打点 + CI 接入 | wrapping tracer / top kinds / `PROFILE=1` |
| **0.2.13-eng** | CI 工具链 + trace 导出 + bench 摘要 | `ci_tools.sh` / `trace_export` / `bench_summary` |
| **0.2.12-eng** | bench baseline 对照 + alloc 热点 | `bench_compare --ci` / `alloc_hotspot` / `kb_delta` |
| **0.2.11-eng** | bench 扩展 + `flow_doctor` / trace lane·chan | 性能表与周边工具可 CI / 复测 |

完整变更细节见 [`CHANGELOG.md`](../CHANGELOG.md)；能力边界见 [`tabMachine对照.md`](tabMachine对照.md)。

## 路线收口：已完成与有意推迟

本轮目标是**对齐有用能力子集**，不是把 Cont/CPS 改造成完整 tabMachine。

### 已完成（0.2.17-eng）

- 复杂可运行示例：`examples/escort_mission/`（lanes / proxy / chan / supervise / with_timeout / pause·finally）
- 复杂可运行示例：`examples/worker_pool/`（有界 chan 背压 / map_parallel / supervise / lanes）
- `tests/run.lua` smoke（quiet assert）；主 README 入口链接

### 已完成（0.2.16-eng）

- 本机重种 [`tools/bench_baseline.json`](../tools/bench_baseline.json)（`lua5.3 tools/bench_compare.lua --write-baseline`，N=20000）
- [`docs/工具套件收口.md`](工具套件收口.md)：全工具 inventory、日常/CI 工作流、游戏时间勿用 `wait_real`
- **eng 工具波次视为完成**（无 Tab DSL；再发现 bug 按单点修）

### 已完成（0.2.15-eng）

- `tools/scenarios/`：`sync_seq` / `wait_vc` / `lane_pair` / `chan_ping` / `supervise_once`；bench/profile/trace 复用
- [`docs/工具速查.md`](工具速查.md)：一页全工具 copy-paste 命令
- **无 Tab DSL**

### 已完成（0.2.14-eng）

- `tools/profile_flow.lua`：wrapping tracer，`os.clock`/墙钟打点，按 yield kind（+step）汇总 top；场景 sync/wait/lane/chan；`--json` / `--smoke`
- `scripts/ci_tools.sh`：末步始终 profile smoke；`PROFILE=1` 加深

### 已完成（0.2.13-eng）

- `scripts/ci_tools.sh`：测试 + `flow_doctor --ci` + `bench_compare --ci` + `alloc_hotspot` smoke；`ALLOW_BENCH_REGRESSION=1` soft-fail
- `tools/trace_export.lua`：`opts.trace` → JSON 文件（`--lane` / `--chan` / `--out`）
- `tools/bench_summary.lua`：bench JSON → Markdown 表

### 已完成（0.2.12-eng）

- `bench_compare` / `bench_baseline.json`：Δ% 对照与 `--ci` 回归（默认 25%）
- `bench_cont_fx --alloc` + JSON `kb_delta`；`alloc_hotspot` 分配快照

### 已完成（0.2.11-eng）

- stop / abort / cancel、`iquit` / `finally`、`seq`、join/select、suspend/resume。
- 命名 lane、多 lane 汇合，以及轻量 proxy 的跨 session wait/stop/abort。
- Unity + Lua 5.3 的 Scheduler、主线程 resume、实体销毁取消、注册表与验收回归。

### 有意推迟（不阻塞工程可用）

- **完整 tab DSL / tab 树**：保留 Cont/CPS 主线，不引入完整代理树、output/事件转发链。
- **`xx_update` 标签作为一等调度语义**：当前使用 `fx.wait_until` / `schedule_poll` 表达轮询。
- **UI binding tree**：当前由 Unity handler、`fx.bind_entity` 与业务层自行组织 UI 生命周期，不复制 tabMachine 的 UI 绑定树。

若未来需求明确要求上述能力，应作为独立路线评估，而不是把当前轻量 lane/proxy 误认为完整兼容层。

## Unity 集成推荐阅读顺序

按“语义 → Lua 约束 → 引擎桥接 → 工程验收”的顺序阅读：

1. **本页**：确认版本边界、工具套件收口与 0.2.11 路线边界。
2. [工具套件收口](工具套件收口.md) / [工具速查](工具速查.md)：bench 与周边怎么用；游戏逻辑勿用 `wait_real`。
3. [Lua 5.3 兼容性](Lua53兼容性.md)：先确认宿主版本、`__shr` 等兼容约束。
4. [CPS 设计与原理](CPS设计与原理.md)：理解 Cont/Coro/CPS 的 Done/Yielded/Stopped/Failed 模型。
5. [异步效果同步写法](异步效果同步写法.md)：掌握 `fx.wait`、fork/join、when_all/any、timeout 和 cancel。
6. [Unity 对接](Unity对接.md)：按 scaled 游戏时间、主线程桥接和实体销毁设计宿主。
7. [`host/unity/README.md`](../host/unity/README.md)：照拷贝清单接入 `LuaGameScheduler`、`FxUnityBootstrap` 和 C# 模板。
8. [工程对接与后续](工程对接与后续.md)：核对 Scheduler、效果注册、生命周期与分层约定。
9. [工程可用验收](工程可用验收.md)：执行回归项并确认已完成/有意推迟的 parity scorecard。
10. [API 参考](API.md) 与 [tabMachine 对照](tabMachine对照.md)：实现具体调用或核对 tabMachine 边界时查阅。

最小回归命令：

```bash
lua5.3 tests/run.lua
```

Unity 无编辑器时，可先运行 `host/unity/MockUnityHost.lua` 的冒烟示例，再接真实 `UnityHost`。
