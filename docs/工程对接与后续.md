# Cont / fx 工程对接与后续规划

本文记录：在「演示级」Cont/Coro/withEnv/fx 之上，若要对接**正式游戏工程**，约定如何分层、先做什么、后做什么。  
**不绑定** tabMachine 糖衣方案；业务书写仍以本仓库 Cont 主线为准。

**目标宿主：Unity + Lua 5.3**（xLua / tolua / slua 等；不强制某一插件）。  
Unity 专用步骤、scaled 时间、主线程桥接、拷贝模板见 **[Unity对接.md](Unity对接.md)**。  
Lua 5.3 验证与 `__shr` 说明见 **[Lua53兼容性.md](Lua53兼容性.md)**（`lua5.3 tests/run.lua` 已通过）。

## 1. 演示与工程的分界

| | 演示（当前主线能力） | 工程（对接游戏项目时要补齐） |
|--|--|--|
| 时间 | `busy_wait` / 墙钟近似 | **游戏时间**定时器唤醒 |
| 效果 | mock `wait`/`connect`/`click` | **可注册**的真实 `kind` + 引擎 handler |
| 驱动 | `fx.run` 一次跑完或内部睡 | **不阻塞主线程**；到点/到事件再 resume |
| 生命周期 | `init`/`finally`、cancel 树 | 与**实体销毁/切场景**绑定，保证清 timer |
| 可观测 | `__Trace__`、打印 | 按 flow id 的结构化追踪（可后置加深） |

演示证明语义能写；工程证明：**接上游戏时间与 I/O、能取消干净、出事能查**。

## 2. 推荐分层（对接正式工程）

```text
游戏业务（withEnv 步骤 / Cont 管道 / fx.when_all|fork|…）
              │
              ▼
     Session 调度器（已有：fx_sched / run_session）
       · 多任务、fork/join、when_all/any
       · Yielded 解释、取消传播、finally
       · 遇到 kind=wait → 交给「时间后端」，不再自己 sleep
              │
              ▼
     游戏时间 Scheduler（工程侧适配，待接）
       · now() / schedule(delay, cb) / cancel(handle)
              │
              ▼
     引擎定时器 / 消息 / 其它子系统
```

### 2.1 Session 调度器（保留）

现有 **session 调度器是 Cont/fx 的运行时核心**，对接工程时**不要换成另一套协程 VM**，也不要让引擎定时器直接理解 Cont。

职责继续包括：

- 驱动 Done / Yielded / Stopped / Failed
- `fork` / `join` / `when_all` / `when_any` / `map_parallel`
- 取消树、`cancel_siblings`
- 与 `init` / `finally` 的退出清理配合

### 2.2 游戏时间 Scheduler（时间后端）

只解决一件事：**`wait` / 超时何时被唤醒**。

| 方法 | 含义 |
|------|------|
| `now()` | 当前**游戏时间**（逻辑秒） |
| `schedule(delay, cb)` | 游戏时间再过 `delay` 秒后回调 |
| `cancel(handle)` | 取消尚未触发的回调 |

约定：

- **默认只用游戏时间**，与暂停 / 慢放 / 加速一致；墙钟 `fx.wait_real` 为 **opt-in**（`schedule_real` / `allow_real_time`），默认 Failed。
- 游戏暂停时：已挂起的 `wait` **不**唤醒；恢复后按剩余游戏时间继续。
- `cancel`（切场景、毁实体）：即使暂停中也要清 timer，并走 `Stopped` + `finally`。

Session 侧改造点（实现时）：

1. 任务 `Yielded{kind=wait}` → `handle = timer.schedule(...)`，把 handle 记在任务上。  
2. 回调触发 → 只 resume 该 wait，再让 session 继续。  
3. 取消 / stop → `timer.cancel(handle)`，再走现有终态路径。  
4. `with_timeout` → 超时 timer + 取消另一方，语义仍为 `Failed("timeout")`（或文档已定错误值）。

**帧循环不是 Cont 的必需驱动**：若引擎已有游戏时间定时器，优先接定时器；仅在需要每帧 poll（`wait_until`）或没有可靠 timer 时，再提供基于 `tick(dt)` 的 FrameScheduler 作为第二种后端。

### 2.3 效果注册表

业务只 `Coro.yield({ kind = "...", ... })`；引擎侧注册 handler：

- 瞬时：当帧兑现（如播一声 SFX 的 fire-and-forget，若需要等待完成则用跨帧 kind）
- 跨帧：动画、寻路等 → 完成后 resume
- 时间：统一走 Scheduler，而不是 handler 里 sleep

稳定 `kind` 契约与版本，避免业务私造未注册 kind。

### 2.4 事件

`wait_event(name, filter?)`（✅ 已落地）：`fx.wait_event` + 宿主 `listen`/`emit`（见 GameSim）；与时间后端正交，可与 timer 并行推进。

## 3. 与实体 / 场景生命周期

| 游戏事件 | Cont/fx 侧 |
|----------|------------|
| 实体销毁、流程被打断 | `cancel` 对应 session；清所有相关 timer；保证 `finally` |
| 切场景 | 取消场景内未完成 flow；或显式「跨场景保留」白名单（工程策略） |
| 暂停 | 仅影响游戏时间 timer；cancel 仍立即生效 |

不变量（应对齐测试）：

- 正常 Done、`stop`/`cancel`、timeout Failed 三条路都进入约定的清理（`finally` / 资源 scope）。
- 已 cancel 的 wait **不得**再被迟到的 timer 回调 resume（cancel 必须拆 handle）。

## 4. 后续功能清单（按优先级）

### P0 — 对接最小闭环

1. **Scheduler 接口** + 游戏时间定时器适配（替换 wait 忙等）。 ✅ `scheduler.lua` / `GameSim` / `opts.scheduler`  
2. **取消时 clearTimeout** 与「迟到回调忽略」语义。 ✅  
3. **效果注册**协议（文档 + `register` API）。 ✅ `fx.register` / `fx_registry` + `GameSim:register`；未知 kind → Failed  
4. 将上述不变量写成测试（可用**虚拟游戏时钟** `advance(dt)`，单测不依赖真引擎）。 ✅  

### P1 — 游戏常用

5. `wait_event`（或等价 kind）。 ✅ `fx.wait_event` + `GameSim:emit`  
6. 资源作用域强化（嵌套 bracket；与 fork 子树绑定释放）。 ✅ `fx.with_resource` / `Cont.bracket`；嵌套内先外后；超时取消子树时各 bracket 仍 release  
7. 截止时间向下传播（子 fork 继承 deadline）。 ✅ `deadline_abs` 继承；超时递归 Stopped + finally；`opts.timeout`/`deadline`  
8. 轻量 flow 追踪（步骤进入/离开、yield kind、取消原因）。 ✅ `opts.trace` / `fx.set_tracer`（默认关闭）  
8b. 实体绑定助手。 ✅ `fx.bind_entity` / `fx_flow`（GameSim / Unity OnDestroy 同模式）

### P2 — 按需

9. FrameScheduler / `wait_until(pred)`（每帧 poll）。 ✅ `scheduler.FrameScheduler`；`fx.wait_until`；GameSim.`schedule_poll`  
10. 有界 channel / mailbox（多 flow 协作）。 ✅ `fx.chan` / `send` / `recv` / `close`  
11. 监督式重启策略。 ✅ `fx.supervise`（max_restarts/backoff/restart_if；cancel 不重启）  
12. ~~墙钟 `wait_real`~~ → **已落地（0.2.8-eng，opt-in）**。  
13. 持久化续延、多线程——与合作式 Cont 模型冲突或成本高，默认不做。

## 5. 宿主回调线程（对接时确认）

引擎 timer 回调是否在**主逻辑 / 主 Lua 状态**：

| 情况 | 建议 |
|------|------|
| 主线程回调 | 可在回调内直接推进 session |
| 其它线程或受限上下文 | 回调只投递「wait 到期」到主循环队列，下一拍再 resume |

**Session 推进应发生在允许碰游戏对象的上下文**；具体由适配层保证，不泄漏给业务 Cont 代码。

---

## 6. 业务侧推荐写法（工程中）

- 流程：`Cont.withEnv` + 普通步骤 / Cont 步骤；生命周期用 `init` / `finally`。  
- 并行：`when_all` / `fork`+`join` / `map_parallel`（已有）。  
- 超时：`with_timeout`（已有；接 Scheduler 后改为游戏时间）。  
- 不要在步骤里直接 `os.execute("sleep")` 或墙钟忙等。  
- 引擎专有能力：注册新 `kind`，或薄封装成 `fx.xxx` 风格助手，仍走 yield。

Cont/fx **不**替代实体组件、物理、渲染；只替代「长流程 / 异步步骤」的组织方式。

## 9. 参考宿主：`GameSim`（本仓库已实现）

近真实模拟宿主，对接上文分层，**不**依赖真引擎：

| 模块 | 路径 |
|------|------|
| Scheduler 接口 / VirtualClock | [`src/scheduler.lua`](../src/scheduler.lua) |
| 游戏模拟宿主 | [`src/game_sim.lua`](../src/game_sim.lua) |
| session 异步 wait | [`src/fx_sched.lua`](../src/fx_sched.lua)（`opts.scheduler`） |
| `fx.wait_event` | [`src/fx.lua`](../src/fx.lua) |
| 效果注册表 | [`src/fx_registry.lua`](../src/fx_registry.lua)（`fx.register`） |
| 实体绑定 / start_flow | [`src/fx_flow.lua`](../src/fx_flow.lua)（`fx.bind_entity`） |
| 资源 bracket | `fx.with_resource` / `Cont.bracket` |
| 轻量追踪 | `opts.trace` / `fx.set_tracer` |
| 工程验收清单 | [`工程可用验收.md`](工程可用验收.md) |

### API 摘要

```lua
local GameSim = require("game_sim")
local fx = require("fx")
local Cont = require("cont")

local sim = GameSim.new({ dt = 1/30 })

-- Scheduler
sim.now() / sim.schedule(delay, cb) / sim.cancel(handle)
sim:set_paused(true|false)   -- pause 时 tick 不推进游戏时间

-- 驱动
sim:tick(dt)                 -- 推进游戏时间并触发到期 timer
sim:start_flow(entity?, ma, handlers?, opts?)  -- 返回 flow { cancel, done, result }
sim:run(ma, handlers?, opts?)                  -- 内部 tick 直到终态（测试友好）

-- 事件
fx.wait_event(name, filter?)
sim:emit(name, payload?)

-- 实体
local e = sim:spawn_entity("mob")
sim:start_flow(e, ma)        -- 绑定
sim:destroy_entity(e.id)     -- 取消绑定 flow + finally

-- 自定义 kind（可选异步）
sim:register("anim", function(req, resume)
  sim.schedule(req.seconds or 1, function() resume({ ok = true }) end)
end, { async = true })
```

### 如何运行示例

```bash
# 仓库根目录
lua examples/game_sim_flow.lua       # wait / pause / wait_event / 实体 finally / anim
lua examples/game_sim_parallel.lua   # when_all、fork/join 走游戏时间（无墙钟忙等）
lua tests/run.lua                    # 含 GameSim 断言
lua examples/dungeon_raid/main.lua   # 综合地牢 demo（通关叙事）
```

无 `opts.scheduler` 时 `fx.run` **保持旧行为**（`busy_wait` / 墙钟 deadline），演示路径兼容。
