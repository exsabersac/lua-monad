## 1A. tabMachine parity scorecard

本仓库只承诺**有用能力子集的轻量对齐**，不承诺完整 tabMachine 克隆。✅ 表示已有 API、工程宿主路径和测试/验收入口；❌ 表示明确的路线留白，不是 0.2.10 的遗漏。逐项语义见 [tabMachine 对照](tabMachine对照.md)。

### 已完成

| 能力面 | 当前入口 | 验收口径 |
|--------|----------|----------|
| 终态与清理 | `stop` / `abort` / `cancel`、`iquit`、`finally` | Stopped/Aborted/Failed 的传播和退出顺序明确 |
| 组合与竞速 | `fx.seq`、`join`、`when_all` / `when_any` | 串联、汇合、竞速及 abort 传播可回归 |
| 挂起与多行 | `flow:suspend/resume`、`fx.lane(s)` | flow 级冻结；命名子流和汇合可用 |
| 代理与协作 | `fx.proxy`、`fx.chan`、Scheduler | 轻量 tabProxy、跨 flow mailbox、游戏时间调度可接 Unity |
| Unity 工程闭环 | Bootstrap、主线程 resume、实体绑定 | `LuaGameScheduler` / `FxUnityBootstrap` / `fx.bind_entity` 有模板和验收路径 |

### 有意推迟

| 项目 | 当前策略 | 是否阻塞工程可用 |
|------|----------|------------------|
| **完整 tab DSL / tab 树** | 保持 Cont/CPS；lane/proxy 仅做轻量映射，不实现完整代理树和 output/事件链 | 否 |
| **`xx_update` 标签作为一等语义** | 用 `fx.wait_until` / `schedule_poll` 表达每帧或间隔轮询 | 否 |
| **UI binding tree** | 用 Unity handler、`fx.bind_entity` 和业务层生命周期组织 UI | 否 |

这三项属于未来需求驱动的独立路线；当前验收以“工程闭环 + 明确边界”为准。

## 3. 距「工程可用标准已达标」还剩什么

**以本清单 §1 Acceptance（含截止继承、wait_until / FrameScheduler）为准：核心工程闭环已齐，可视为已达标。**

仍属**可选增强**（不阻塞达标；部分已落地）：

| 项 | 说明 |
|----|------|
| `fx.wait_real` | ✅ opt-in（0.2.8-eng）；网络/SDK；默认业务用 `fx.wait` |
| `fx.lane` / `lanes` | ✅ 0.2.9-eng；命名子流 ≈ tabMachine `c:start`；见对照文档 |
| `fx.proxy` / `flow:proxy` | ✅ 0.2.10-eng；轻量 tabProxy；`proxy_join`/`stop`/`abort`；可选 `stop_host_when_stop` |
| 完整 tab DSL / tab 树 | ❌ 有意推迟；Cont/CPS 主线不引入完整代理树和 output/事件转发链 |
| `xx_update` 标签作为一等语义 | ❌ 有意推迟；当前用 `wait_until` / `schedule_poll` |
| UI binding tree | ❌ 有意推迟；当前用 Unity handler + `fx.bind_entity` + 业务生命周期 |

演示回退：无 `opts.scheduler` 时 `wait` / `wait_until` 仍可能走 `busy_wait`——**仅 demo / 单测便利，工程请接 GameSim / FrameScheduler / Unity host**。
