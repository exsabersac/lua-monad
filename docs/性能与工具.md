# 性能与工具

目标宿主：**Unity + Lua 5.3**。热路径粗测与周边工具说明（版本 **`0.2.15-eng`**）。

## 瓶颈（测什么）

`tools/bench_cont_fx.lua` 与实现注记：压力主要来自

1. **每步 Cont 代理表**（`setmetatable({ _fn = … }, mt)`）
2. **`>>` / `bind` 闭包**（构造时一层、求值时再包续延）
3. **`Cont.unit` 再包一层**（`ma >> function(x) return Cont.unit(f(x)) end` 时尤其明显）
4. session / `fx.run` 调度（无 Yield 时已走同步快路径；有 wait/fork/lane/chan 仍由 session 主导）

**未做**（风险高）：Answer（Done/Yielded）对象池——调用方可能持有 Answer，复用易脏读。优先安全路径。

## 0.2.4-eng 已做优化

| 改动 | 效果 |
|------|------|
| **Cont.bind** 专用实现 | 去掉 makeMonad 的 bind-time adapter；`f` 返回已 wrap 的 Cont 时直接调 `_fn(k)` |
| **Cont.chain(ma, mb)** | ≡ `ma >> (_ → mb)` / `ma .. mb`，无用户闭包 |
| **Cont ..** | 走 `chain` |
| **Cont.map / then_ / fmap** | 直接改续延，避免 `bind+unit` 双代理 |
| **fx.seq** | 用 `Cont.chain` 串联 |

## 0.2.5-eng 同步快路径

| 改动 | 效果 |
|------|------|
| **`fx_sched.start_session` / `run_session`** | `Coro.start(ma)` 后若立刻 **终态**（Done / Stopped / Aborted / Failed，从未 Yield），跳过 nursery / pump，返回 settled flow |
| Yielded | 把已 start 的 Answer 注入 `alloc_task`，走既有 session（wait/fork/timeout/cancel/finally/iquit 不变） |
| cancel | 与 pump 一致：Cont 已求值完毕后若 `opts.cancel` 已真 → `stopped/cancelled` |
| trace | 仍发 `flow_start` + `done`\|`stopped`\|`failed`\|`aborted`（cancel 时多 `cancel`） |

适用：纯 `Cont.unit` / `bind` / `seq` / 即时 `stop`·`abort`·`fail`（含已跑完的 finally/iquit）。  
不适用：任意 `wait` / `fork` / `when_*` / `lane` / `chan` / 自定义 yield effect——这些从 `start` 起即 Yielded。

**解读**

- **`>>` 热路径**：约 **+15–25%** 吞吐（0.2.4）；至今仍稳定。
- **纯映射**：优先 `Cont.map` / `then_`（约 **2×** 于 `>> unit`）。
- **丢弃左值 / seq**：用 `Cont.chain` 或 `..` / `fx.seq`。
- **`fx.run(seq)` 无异步**：同步快路径把时间从 session 主导拉到接近 Cont 求值量级。
- **lane / proxy_join**：同量级（命名表 + join nursery）；适合对照 tabMachine 多行/proxy，勿当微秒热路径。
- **chan**：缓冲 send/recv 同 session 约 2–3×10⁴ /s；GameSim 构造开销已含在内。
- **supervise fail→ok**：含一次 Failed 重启，吞吐接近 lane。
- **wait_until 平凡 pred / when_all waits**：有 Yield 的 session 路径；作并行与轮询对照。

复现：

```bash
lua5.3 tools/bench_cont_fx.lua 20000
lua5.3 tools/bench_cont_fx.lua --json --filter lane
lua5.3 tools/bench_cont_fx.lua --alloc --json --filter 'Cont >>'
lua5.3 tools/bench_compare.lua --ci
```

## 工程建议

1. 能 `map` 就不要 `>> unit`。
2. 顺序丢弃用 `Cont.chain` / `..` / `fx.seq`，勿每步新建 `function(_) return next end`。
3. 纯同步管道可直接 `fx.run`；无 Yield 时不再付 nursery 税。有异步效果时仍复用 **session / flow**。
4. 游戏逻辑的 `wait` / `wait_until` **务必**注入 `opts.scheduler`（VirtualClock / GameSim / Unity）；无 scheduler 会走 busy_wait（`flow_doctor` 会 WARN）。
5. Trace 默认关；排查时用 `tools/trace_dump.lua`（stdout）或 `tools/trace_export.lua`（JSON 文件；`--lane` / `--chan`）或 `opts.trace = fn`。
6. 场景耗时拆分：`tools/profile_flow.lua`（wrapping tracer；场景见 `tools/scenarios/`；`--smoke` / `--json`）。
7. CI 推荐 `./scripts/ci_tools.sh`（含 doctor + bench --ci + alloc smoke + profile smoke）；`PROFILE=1` 加深 profile；也可单独 `lua5.3 tools/flow_doctor.lua --ci`。
8. bench 摘要：`lua5.3 tools/bench_summary.lua --out tools/bench_summary.md`。

## 工具入口

见 [`tools/README.md`](../tools/README.md) / 一页 [`工具速查.md`](工具速查.md)：

- `scripts/ci_tools.sh` — 测试 + doctor + bench --ci + alloc smoke + profile smoke（`ALLOW_BENCH_REGRESSION=1` / `PROFILE=1`）
- `scenarios/` — 可复用 Cont/fx 场景（bench/profile/trace 共用）
- `bench_cont_fx.lua` — 热路径 + ΔKB；`--json` / `--filter` / `--alloc`（JSON 含 `kb_delta`）
- `bench_compare.lua` / `bench_baseline.json` — 基线对照、`--write-baseline`、`--ci` 回归
- `bench_summary.lua` — JSON → Markdown 表（`--out` / `--stdin` / `--from`）
- `profile_flow.lua` — Cont/fx 场景 wrapping tracer 打点；top kinds；`--json` / `--smoke`
- `alloc_hotspot.lua` — Cont `>>` 分配热点快照
- `flow_doctor.lua` — 误配置检查 + `STANDARD_KINDS`；CI flag / `--ci`
- `trace_dump.lua` — trace 事件 dump（`--json` / `--wait` / `--lane` / `--chan`）
- `trace_export.lua` — trace 事件导出 JSON 文件（默认 `tools/trace_out.json`）
- `mdo.lua` / `run_mdo.lua` — do 语法预处理
