# 性能与工具

目标宿主：**Unity + Lua 5.3**。热路径粗测与周边工具说明（版本 **`0.2.5-eng`**）。

## 瓶颈（测什么）

`tools/bench_cont_fx.lua` 与实现注记：压力主要来自

1. **每步 Cont 代理表**（`setmetatable({ _fn = … }, mt)`）
2. **`>>` / `bind` 闭包**（构造时一层、求值时再包续延）
3. **`Cont.unit` 再包一层**（`ma >> function(x) return Cont.unit(f(x)) end` 时尤其明显）
4. session / `fx.run` 调度（无 Yield 时已走同步快路径；有 wait/fork 仍由 session 主导）

**未做**（风险高）：Answer（Done/Yielded）对象池——调用方可能持有 Answer，复用易脏读。优先安全路径。

## 0.2.4-eng 已做优化

| 改动 | 效果 |
|------|------|
| **Cont.bind** 专用实现 | 去掉 makeMonad 的 bind-time adapter；`f` 返回已 wrap 的 Cont 时直接调 `_fn(k)` |
| **Cont.chain(ma, mb)** | ≡ `ma >> (_ → mb)` / `ma .. mb`，无用户闭包 |
| **Cont ..** | 走 `chain` |
| **Cont.map / then_ / fmap** | 直接改续延，避免 `bind+unit` 双代理 |
| **fx.seq** | 用 `Cont.chain` 串联 |

## 0.2.5-eng 同步快路径

| 改动 | 效果 |
|------|------|
| **`fx_sched.start_session` / `run_session`** | `Coro.start(ma)` 后若立刻 **终态**（Done / Stopped / Aborted / Failed，从未 Yield），跳过 nursery / pump，返回 settled flow |
| Yielded | 把已 start 的 Answer 注入 `alloc_task`，走既有 session（wait/fork/timeout/cancel/finally/iquit 不变） |
| cancel | 与 pump 一致：Cont 已求值完毕后若 `opts.cancel` 已真 → `stopped/cancelled` |
| trace | 仍发 `flow_start` + `done`\|`stopped`\|`failed`\|`aborted`（cancel 时多 `cancel`） |

适用：纯 `Cont.unit` / `bind` / `seq` / 即时 `stop`·`abort`·`fail`（含已跑完的 finally/iquit）。  
不适用：任意 `wait` / `fork` / `when_*` / 自定义 yield effect——这些从 `start` 起即 Yielded。

## 粗测数字（本机 box，Lua 5.3.6，N=20000）

非严格 microbench（含 GC）；取三次运行的大致中位。

### 优化前（`07c9b47`，仅旧四项）

| 项 | 时间 | 吞吐 |
|----|------|------|
| Cont >> chain | ~0.029 s | ~6.9×10⁵ /s |
| Coro.start unit | ~0.016 s | ~1.3×10⁶ /s |
| fx.seq×3 run | ~3.23 s | ~6.2×10³ /s |
| session wait(0) N=5000 | ~0.084 s | ~6.0×10⁴ /s |

### 0.2.4-eng（Cont 热路径，尚无 sync fast-path）

| 项 | 时间 | 吞吐 | ΔKB（约） |
|----|------|------|-----------|
| Cont >> chain | ~0.023–0.028 s | ~7.2–8.8×10⁵ /s | ~7814 |
| Cont.map chain | ~0.010–0.012 s | ~1.7–2.0×10⁶ /s | ~3880 |
| Cont.chain / .. | ~0.019–0.021 s | ~9.5–10.8×10⁵ /s | ~5157 |
| Coro.start unit | ~0.015 s | ~1.3×10⁶ /s | 波动 |
| fx.seq×3 eval | ~0.050–0.053 s | ~3.8–4.0×10⁵ /s | ~136 |
| fx.seq×3 run | ~3.2 s | ~6.2×10³ /s | session 主导 |
| session wait(0) N=5000 | ~0.080–0.083 s | ~6.0×10⁴ /s | — |

### 0.2.5-eng（+ 无 Yield 同步快路径）

| 项 | 时间 | 吞吐 | ΔKB（约） | 相对 0.2.4 |
|----|------|------|-----------|------------|
| Cont >> / map / chain | 同左表量级 | — | — | 无变化 |
| Coro.start unit | ~0.015 s | ~1.3×10⁶ /s | — | — |
| fx.seq×3 eval | ~0.050 s | ~4.0×10⁵ /s | — | — |
| **fx.seq×3 run** | **~0.13–0.15 s** | **~1.4–1.5×10⁵ /s** | ~300–640 | **约 22×** |
| session wait(0) N=5000 | ~0.080–0.084 s | ~6.0×10⁴ /s | — | 有 Yield，不变 |

**解读**

- **`>>` 热路径**：约 **+15–25%** 吞吐（0.2.4）。
- **纯映射**：优先 `Cont.map` / `then_`（约 **2×** 于 `>> unit`，ΔKB 近半）。
- **丢弃左值 / seq**：用 `Cont.chain` 或 `..` / `fx.seq`。
- **`fx.run(seq)` 无异步**：0.2.5 同步快路径把时间从 session 主导拉到接近 Cont 求值量级（仍略高于 `eval`，因 `Coro.start` + result/trace）。
- **有 wait/fork**：仍走完整 session；`session wait(0)` 数字可作对照。

复现：

```bash
lua5.3 tools/bench_cont_fx.lua 20000
```

## 工程建议

1. 能 `map` 就不要 `>> unit`。
2. 顺序丢弃用 `Cont.chain` / `..` / `fx.seq`，勿每步新建 `function(_) return next end`。
3. 纯同步管道可直接 `fx.run`；无 Yield 时不再付 nursery 税。有异步效果时仍复用 **session / flow**。
4. Trace 默认关；排查时用 `tools/trace_dump.lua` 或 `opts.trace = fn`。
