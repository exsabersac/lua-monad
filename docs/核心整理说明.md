# 核心整理说明（0.2.20-eng）

行为保持前提下的调度器拆分与去重说明。公共 API 不变：`require("fx_sched")` / `fx.lua` 表面与原先一致。

## 0.2.20-eng：fx 扩展再简化

- **文档两层**：[`fx分层.md`](fx分层.md) — Core（推荐心智）与 Sugar（可选）；不删公共名。
- **`fx.lua`**：`yield_unit` / `yield_join` / `yield_control` 共用；按 Core / Sugar 分区；薄包装。行数约 **921 → 664**。
- **sched（低风险）**：`S.join_finished_or_park` 供 fork / lane / proxy join 共用。
- 示例 escort / worker / dungeon 行为不变。

### 重复与难跟读处（审计）

1. **终态 / join 唤醒**：`try_complete_joins`、`settle_group`、`join` / `join_handles` 即时路径多次手写 `Failed` / `Aborted` / `Stopped` 分支。
2. **timer 回调样板**：`wait` / `wait_real` / `wait_event` / 通用 async handler 共用「flag.cancelled → when_flow_active → resume → `_pump`」骨架。
3. **supervise 清理**：`settle_group` 四个失败分支各调一次 `clear_supervise_backoff` + 清 `waiting_group`。
4. **前向声明网**：`drive_until_block` ↔ `on_task_terminal` ↔ `settle_group` ↔ `cancel_descendants` ↔ supervise 互相引用，单文件靠 `local x` 前向声明，拆文件后改用共享袋 `S` 晚绑定。
5. **`drive_until_block` 巨型 if/elseif**：0.2.19 已拆成 kind → handler 表。

### kind 分派约定

- `S.drive_handlers[kind] = function(nursery, task, req) → status|nil`
- 返回非空字符串（`"wait"` / `"parked"` / `"failed"` / …）→ `drive_until_block` 立刻返回该状态
- 返回 `nil` → 已 resume / 继续 while 循环
- 未登记 kind → `drive_handlers.__registry`（opts.handlers / `fx_registry` / async）

## 已做去重

- `arm_scheduler_timer`：scheduler 路径下 wait / wait_real 共用登记与回调。
- `apply_finished_child_to_waiter`：join / lane_join / proxy_join（同 nursery 已结束子）共用。
- `settle_group` 内 supervise 清理收成局部一步（0.2.18）。
- **0.2.19**：`drive_until_block` 不再含 kind 分支体，只查表分派。

## 有意保留的债务（后续）

1. `fx_sched_nursery.lua` 仍集中 terminal+join+cancel；与 drive/session 循环依赖靠 `S` 晚绑定，可读性好于单文件但仍需脑内跟引用。
2. `cont_env.lua` 体量大，属 Cont 环境组合，与调度正交，单独波次再整理。
3. ~~`fx.lua` 别名未收口~~ → 0.2.20 已按 Core/Sugar 分区并共用 yield 辅助。
4. wait_until / async registry 仍有相近的「flag + when_flow_active + pump」样板，可再抽 `resume_task_and_pump`（本轮未动，降风险）。
