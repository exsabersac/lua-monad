# 异步效果的同步写法（`fx`）

教学层：用 **看起来同步** 的 `Cont.withEnv` 步骤管道书写业务，把 wait / 网络连接 / 点击等 **异步效果** 表达成 `Coro.yield` 请求，由外部解释器兑现；并用 **Stopped / Failed** 表达停止与失败；用 **when_all / when_any** 对齐 C# `Task.WhenAll` / `Task.WhenAny`；用 **fork / join** 对齐非结构化的 `Task.Run` + `await task`。

| 角色 | 模块 | 职责 |
|------|------|------|
| 业务管道 | `Cont.withEnv` | 按名顺序 `>>`；步骤里调用 `fx.*` |
| 效果原语 | [`src/fx.lua`](../src/fx.lua) | `wait` / `wait_event` / `wait_until` / **`chan`·`send`·`recv`** / `connect` / `click` → yield；`stop` / `fail` → 终态；`when_all` / `when_any`；`fork` / `join`；`map_parallel`；`with_timeout`；**`supervise`** |
| 并行调度 | [`src/fx_sched.lua`](../src/fx_sched.lua) | nursery session + 时间轮：动态任务集；wait 登记 deadline；fork 立刻返回 handle |
| CPS 挂起 | [`src/coro.lua`](../src/coro.lua) | `Done` \| `Yielded` \| `Stopped` \| `Failed` |
| 解释器 | `fx.run` / `fx.run_parallel` | 整段走 `run_session`；`opts.cancel` 协作取消 |

## 与 C# async/await 对照

| C# | 本库 |
|----|------|
| `Task.Delay(ms)` | `fx.wait(seconds)` |
| `await` | `Coro.yield` + `resume`（藏在 `fx.run` / 调度器里） |
| `Task.WhenAll(...)` | `fx.when_all` / `fx.run_all` / `fx.run_parallel(..., {mode="all"})` |
| `Task.WhenAny(...)` | `fx.when_any` / `fx.run_any` |
| `Task.Run(...)` / 启动子任务 | `fx.fork` / `fx.spawn`（立刻得到 handle，不等待） |
| `await task`（已启动的 Task） | `fx.join(handle)` / `fx.join_handles({...})` |
| `CancellationToken` | `opts.cancel`（函数或 `{cancelled=bool}`） |
| `try` / `catch` | `Cont.catch` / `fx.try` / `Failed` |
| `async Task` 方法体 | `Cont.withEnv` 步骤里 `return fx.when_all({...}) >> …` 或 `fork`+`join` |

要点：**业务 API 仍是 Cont Coro 编码**，不是 Lua 原生 `coroutine`；并行只是多个 Answer 由时间轮交替 resume。

## 不是什么

- **不是**真实网络或 UI；默认 handlers 只打印日志并返回 mock 表。
- **不是** Lua 原生 `coroutine` / 已放弃的 `perform`/`runDo`。`Coro.yield` 是 Cont 编码的挂起，业务请走 `fx` / `Coro`，不要当原生协程 API。
- `Cont.withEnv` 只组织 `>>`；挂起与恢复仍由 Coro / `fx.run` / 调度器完成。
- Cont 层异常请用 `Cont.throw` / `Cont.catch`（见 [`examples/cont_catch_throw.lua`](../examples/cont_catch_throw.lua)）；管道中止优先用 `fx.stop` / `fx.fail`。

## 最小形状

```lua
package.path = "src/?.lua;" .. package.path
local Cont = require("cont")
local fx = require("fx")

local pipe = Cont.withEnv(function(_ENV)
  function step(_)
    return fx.wait(0.05) >> function(_)
      return fx.click("ok")
    end
  end
end)

-- fx.run 始终返回结构化结果表（破坏性变更）
local result = fx.run(pipe(nil))
assert(result.ok)
local value = result.value
```

结果表形状：

| 形状 | 含义 |
|------|------|
| `{ ok=true, value=v }` | 正常 `Done` |
| `{ ok=true, values={v1,…} }` | `run_all` / `when_all` 顶层 |
| `{ ok=true, value=v, index=i }` | `run_any` 胜者 |
| `{ ok=false, stopped=true, reason= }` | `fx.stop` / 取消 |
| `{ ok=false, failed=true, error= }` | `fx.fail` |

`fx.wait(seconds)` yield `{ kind="wait", seconds }`，resume 后业务得到 `true`。  
`fx.connect(host, opts?)` / `fx.click(target)` resume 值即结果表。

### 停止与取消

```lua
-- 业务主动停止（不调用后续续延）
return fx.stop("user-abort")

-- 取消令牌：每次 Yielded 前检查；session 取消会停止 nursery 内全部未完成子任务（见「取消传播树」）
local token = { cancelled = false }
-- … 某处 token.cancelled = true
local r = fx.run(pipe(nil), handlers, { cancel = token })
-- r.stopped and r.reason == "cancelled"

-- 或 cancel = function() return boolean end
```

### 失败与 try

```lua
return fx.fail("disk-full")  -- 或 fx.throw（别名）

local r = fx.try(ma, handlers, {
  on_fail = function(err) return { recovered = true, err = err } end,
  on_stop = function(reason) return nil end, -- nil 保持原 stopped
})
```

自定义 handlers（瞬时、记事件）示例见 [`examples/fx_custom_handlers.lua`](../examples/fx_custom_handlers.lua)。

## 并行：WhenAll / WhenAny

### 顶层驱动（教学友好）

```lua
-- ≈ await Task.WhenAll(t1, t2)
local r = fx.run_all({ fx.wait(0.05), fx.wait(0.05) }, handlers, opts)
-- r.ok, r.values = { true, true }
-- 两路各 0.05s：wall clock ≈ 0.05（并行），串行会 ≈ 0.10

-- ≈ await Task.WhenAny(t1, t2)
local w = fx.run_any({ slow, fast }, handlers, opts)
-- w.ok, w.value, w.index
```

`fx.run_parallel(tasks, handlers, { mode="all"|"any", cancel=… })` 是通用入口。

调度器要点（[`fx_sched.lua`](../src/fx_sched.lua)）：

1. 每个任务 `Coro.start`；
2. `wait`：**登记** `deadline = now + seconds`，不在此处串行 `busy_wait`；
3. `connect` / `click`：见到立即走 handlers；
4. 主循环：取最小 deadline → `busy_wait` 到点 → 唤醒所有到期 wait；
5. `when_all`：全部 `Done`；任一 `Failed` / `Stopped` → 整体失败/停止；
6. `when_any`：第一个 `Done` 胜出，其余标为 `Stopped("cancelled")`（不再 resume）。

### Cont 组合子（可放进 withEnv）

```lua
-- 管道内：像 C# async 方法里 await Task.WhenAll(...)
return fx.when_all({
  fx.connect("a"),
  fx.click("b"),
  fx.wait(0.03),
}) >> function(values)
  -- values[1]=conn, values[2]=click, values[3]=true
  return Cont.unit(values)
end

return fx.when_any({ task_a, task_b }) >> function(winner)
  -- winner = { value=..., index=i }
  return Cont.unit(winner)
end
```

`fx.run` 整段走 nursery session：`when_all` / `when_any` / `fork` / `join` 与 wait 时间轮同一驱动（共享 handlers 与 `opts.cancel`）。

别名：`fx.join_all` = `when_all`，`fx.join_any` = `when_any`；`fx.spawn` = `fork`。


## Fork / Join（非结构化并发）

与 `when_all` **互补**：

| | 结构化 `when_all` | 非结构化 `fork` + `join` |
|--|------------------|-------------------------|
| 形状 | 一个表达式里启动并等待全部 | 先 `fork`，中间可 `wait`/`connect`/…，稍后再 `join` |
| 典型 C# | `await Task.WhenAll(a, b)` | `var t = Task.Run(...); …; await t;` |
| 结果顺序 | values 与任务列表对齐 | `join_handles` 与 handle 列表对齐 |

```lua
-- fork 两路慢操作，中间做别的事，再汇合（wall clock ≈ max）
return fx.fork(fx.wait(0.05) >> function(_) return Cont.unit("A") end) >> function(h1)
  return fx.fork(fx.wait(0.05) >> function(_) return Cont.unit("B") end) >> function(h2)
    return fx.connect("mid") >> function(conn)
      return fx.join_handles({ h1, h2 }) >> function(vals)
        -- vals[1]=="A", vals[2]=="B"；conn 已在等待期间完成
        return Cont.unit({ vals = vals, host = conn.host })
      end
    end
  end
end
```

语义要点：

1. `fx.fork(ma)` yield `{ kind="fork", task=ma }`；调度器 `Coro.start` 子任务，立刻 `resume` 父任务为 handle `{ id=number }`。
2. `fx.join(h)` yield `{ kind="join", handle=h }`；子已 `Done` 则立刻取值；否则 park 父任务直到子结束。
3. 子 `Failed` → join 使父 `Failed`（与 `when_all` 一致）；子 `Stopped` → 父 `Stopped`。
4. `fx.join_handles(hs)` 原生多路 join，结果顺序与 handle 列表一致（亦可用 `when_all` of joins，但须在同一 nursery）。
5. 别名：`fx.spawn` = `fx.fork`。
6. `fx.join` / `fx.join_handles` 可选 `opts.cancel_siblings`（见下节「取消传播树」）。

`fx.run` 把根 Cont 放进 **同一 nursery**：父任务、fork 子任务、`when_all` 子任务共享时间轮；嵌套 `fork`（含 `when_all` 子任务内）可行。


## 有限并发池（map_parallel）

`when_all` 一次启动全部任务；`map_parallel` 用 **滑动窗口** 限制同时在飞的 worker 数（≈ 信号量 / 线程池）：

```lua
-- 6 项、concurrency=2：墙钟 ≈ 3 批，而非串行 6 份或全开 1 批
return fx.map_parallel(items, function(item, index)
  return fx.wait(0.04) >> function(_)
    return Cont.unit(item)
  end
end, { concurrency = 2 })  -- 默认 concurrency=4，须 >= 1
```

语义：

1. `worker(item, index)` → `Cont Answer a`；结果数组与 `items` **下标对齐**（同 `when_all`）。
2. 实现：先 `fork` 最多 N 个，按启动顺序 `join`；每完成一个再启动下一个（有界并发）。
3. 空列表 → `Cont.unit({})`。
4. 别名：`fx.for_each_parallel` 同池映射，最终 `Cont.unit(true)`（丢弃各返回值）。

示例：[`examples/fx_map_parallel.lua`](../examples/fx_map_parallel.lua)。


## 超时竞速（with_timeout）

把整段 `Cont Answer` 与 `fx.wait(seconds)` **竞速**：

```lua
-- 限时内完成 → 业务值；超时 → Failed("timeout")
return fx.with_timeout(
  fx.wait(0.05) >> function(_) return Cont.unit("ok") end,
  0.10
)

-- 自定义失败信息（仍为 Coro.Failed，不是 Stopped）
return fx.with_timeout(slow_ma, 0.2, { on_timeout = "deadline-exceeded" })
```

语义：

1. **超时一律 `Failed`**：默认 `error == "timeout"`；`opts.on_timeout` 可换成任意错误值（字符串或表）。不使用 `Stopped`，以便与协作取消（`reason="cancelled"`）区分。
2. `ma` 先 `Done` → 返回其值，并 best-effort 取消计时侧。
3. `ma` 先 `Failed` / `Stopped` → 原样传播（即使尚未到 deadline）。
4. 与 `Cont.withEnv` 的 `__Timeout__`：**属性是逐步（per-step）** 包装；`fx.with_timeout` 包裹 **整段 Cont**（可含多步 wait / when_all 等）。
5. **截止时间向下传播**：`with_timeout` 把绝对截止写入 body；其后 `fx.fork` / `when_all` / `when_any` 子任务继承剩余 deadline（有 `opts.scheduler` 时为**游戏时间**）。
6. 父 deadline 触发时：包装侧 `Failed("timeout")`；body 及其 **未完成后代** 被 `Stopped("cancelled")`（经 `force_stop`，**finally / bracket release 会跑**）。
7. 子任务仍可再包一层更紧的 `with_timeout`（取 `min(子秒数, 父剩余)`）。
8. Session 也可显式设截止：`opts.timeout`（相对秒）或 `opts.deadline`（绝对时钟）；`opts.on_timeout` 自定义 Failed 错误值。

示例：[`examples/fx_with_timeout.lua`](../examples/fx_with_timeout.lua)。


## 截止时间继承（fork）

```lua
-- 父 0.3s 超时；内部 fork 的慢子任务会在超时瞬间被 Stopped，finally 执行
return fx.with_timeout(
  fx.fork(slow_with_finally) >> function(h)
    return fx.join(h)
  end,
  0.3
)

-- 子更紧：先 Failed("child-to")，不必等到父 1.0s
return fx.with_timeout(
  fx.fork(fx.with_timeout(fx.wait(5), 0.1, { on_timeout = "child-to" }))
    >> function(h) return fx.join(h) end,
  1.0
)

-- session 级：相对超时（VirtualClock / GameSim 下为游戏时间）
fx.run(ma, handlers, { scheduler = clock, timeout = 0.25 })
```

| 来源 | 行为 |
|------|------|
| `fx.with_timeout(ma, s)` | body 打上 `now+s`（与父已有 deadline 取更紧）；超时取消 body **及 fork 子树** |
| `opts.timeout` / `opts.deadline` | 根任务打上截止；到期根 `Failed`，未完成子 `Stopped` |
| 子 `with_timeout` | 可再收紧，不可放宽超过继承剩余 |


## 取消传播树

Nursery 内任务形成一棵 **取消传播树**（fork / when_all / with_timeout / map_parallel worker 均挂在父任务下）：

| 触发 | 行为 |
|------|------|
| `fx.run(..., { cancel = token })` 且 token 已取消 | 停止 **全部** 未完成任务（根与子），结果 `{ok=false, stopped=true, reason="cancelled"}` |
| `fx.join(h, { cancel_siblings = true })` | **仅当** join 成功（子 Done）后：停止与 `h` **同一 fork 父** 下、未纳入本次 join 的其它未完成兄弟（`Stopped("cancelled")`） |
| `fx.join_handles(hs, { cancel_siblings = true })` | 同上；兄弟判定相对 `hs` 中各 handle 的共同 fork 父 |
| 父 `with_timeout` / session deadline 到期 | 未完成后代递归 `Stopped`（含 fork 子树）；finally 执行 |

要点：

1. **Session cancel** 是整棵 nursery 的紧急刹车，包含尚在飞的 `map_parallel` worker。
2. **cancel_siblings** 作用域是「同一 `parent_id` 的 fork 兄弟」，不是全局；未 join 的兄弟被 best-effort 标为 `Stopped("cancelled")`，已成功取得的 join 结果不受影响。
3. 与 `when_any` 胜出后取消其它组员类似，但 `cancel_siblings` 由业务在 `join` 时显式打开。

```lua
-- 取第一个完成的快路径，取消同父下仍在跑的慢兄弟
return fx.fork(fast) >> function(hFast)
  return fx.fork(slow) >> function(_hSlow)
    return fx.join(hFast, { cancel_siblings = true })
  end
end
```

示例：[`examples/fx_cancel_tree.lua`](../examples/fx_cancel_tree.lua)。

## 监督式重启（supervise）

子 Cont 失败时按策略重启，对齐「监督者 / 自动重试」一类游戏 AI / 网络流程需求：

```lua
-- 默认：仅 Failed 重启；最多再启 3 次；无 backoff
fx.supervise(child_ma)

fx.supervise(child_ma, {
  max_restarts = 3,   -- 失败后再启次数（总尝试 = 1 + max_restarts）
  backoff = 0.5,      -- 重启前等待（游戏秒；有 opts.scheduler 时走 schedule）
  restart_if = function(err) return true end,  -- 可选；false → 表面失败
  on_fail = function(err) end,                 -- 可选；显式 return false → 不重启
  restart_on_stop = false,  -- true 时 Stopped（非 cancelled）也重启
})
```

| | 说明 |
|--|------|
| Yield | `supervise`（session 内建） |
| 成功 | 子 `Done` → supervise resume 该值 |
| Failed | 若未超 `max_restarts` 且 `restart_if`/`on_fail` 允许 → backoff 后重新 `Coro.start(child)` |
| Stopped | 默认表面停止；`restart_on_stop` 时可重启（`reason=="cancelled"` 永不重启） |
| Aborted | 不重启，表面 `Aborted` |
| cancel | 取消当前子与 backoff timer，**不再重启**；父 `Stopped` |
| finally / iquit | 每次子尝试独立走生命周期；成功跳过 iquit |

## 有界 channel / mailbox

多 flow（或同 session 内 fork）协作，对齐 tabMachine **notify / 邮箱**一类模式，而不是全局事件总线：

```lua
local ch = fx.chan()      -- 默认容量 1（mailbox）；fx.chan(16) 更大缓冲；fx.chan(0) 会合
-- 生产者
fx.send(ch, payload)      -- 满则挂起，直到有 recv
-- 消费者
fx.recv(ch)               -- 空则挂起，直到有 send
fx.close(ch)              -- 可选；之后 send / 空 recv → Failed{ tag="chan_closed" }
fx.is_closed(ch)          -- 同步布尔
```

| | 说明 |
|--|------|
| Yield | `chan_send` / `chan_recv` / `chan_close`（session 内建，无需 register） |
| 唤醒 | peer send/recv/close 时调度器 resume 等待方；**GameSim 路径不 busy_wait** |
| cancel | 从 channel 队列摘掉本任务 waiter → `Stopped`（与 wait/timer 一致） |
| 关闭语义 | 先耗尽缓冲再对空 `recv` 失败；等待中的 `send` 立刻 `chan_closed` |
| 跨 flow | 同一 `ch` 可在多个 `GameSim:start_flow` / `fx.run` 间共享 |

示例扩展：[`examples/game_sim_parallel.lua`](../examples/game_sim_parallel.lua)。

## wait_until / FrameScheduler

当引擎有 `update(dt)` 但定时器弱、或需要每帧 poll 条件时：

```lua
local Scheduler = require("scheduler")
local clock = Scheduler.FrameScheduler()

-- 业务
fx.wait_until(function()
  return enemy.hp <= 0 and "dead"
end, { interval = 0 })  -- 默认每 tick；可设 interval 秒

-- 宿主每帧
function Update(dt)
  clock.tick(dt)  -- 推进时间 + 到期 timer + wait_until polls
end
```

- `opts.scheduler` 为 `FrameScheduler` 或 `GameSim`（均提供 `schedule_poll`）时走每帧 poll。
- 仅有 `schedule` 的 VirtualClock：用自再预约模拟（测试可用）。
- 无 scheduler：演示 busy 轮询，**工程勿用**。
